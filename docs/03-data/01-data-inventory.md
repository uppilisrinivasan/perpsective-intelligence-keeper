# Data inventory

## 1. What Keeper needs, and why

Each methodology step consumes specific data. Anything not in this table is not collected.

| # | Data | Needed for | Real source | Demo source |
|---|---|---|---|---|
| D1 | Repository metadata (name, default branch, licence, visibility) | Context, display | `GET /repos/{o}/{r}` | Generated (code), GitHub schema |
| D2 | Pull requests (list and detail): number, title, body, state, author, association, dates, merge info, head and base SHAs, labels, draft | Situations, triage, outcomes | `GET /repos/{o}/{r}/pulls?state=all`, `GET …/pulls/{n}` | Generated: values by AI (title, body), structure by code |
| D3 | PR files: filename, status, additions, deletions, patch, previous filename | The context block, anchors, risk signals | `GET …/pulls/{n}/files` | Computed by code from real git diffs |
| D4 | Reviews: reviewer, state, body, submitted_at, commit_id | H (review bodies, change requests) | `GET …/pulls/{n}/reviews` | Body by AI; the rest by code |
| D5 | Review comments: path, line, side, start_line, diff_hunk, body, in_reply_to_id, commit IDs | H (inline findings, anchors, threads) | `GET …/pulls/{n}/comments` | Body by AI; anchors and hunks by code from real git |
| D6 | Issue comments on PRs | H (conversation, rejections) | `GET …/issues/{n}/comments` | Body by AI |
| D7 | Issue timeline events: closed, merged, reopened, cross-referenced, review_requested, labeled, head_ref_force_pushed | Rejections, outcomes, links | `GET …/issues/{n}/timeline` | Code |
| D8 | Issues (bugs, features) with labels, links and closing PRs | Outcomes (post-merge bugs) | `GET …/issues?state=all` | Title and body by AI; links by code |
| D9 | PR commits (SHA, author, committer, message, dates) | Maintainer fixes, addressed-or-ignored | `GET …/pulls/{n}/commits` | Real git; messages by AI |
| D10 | Check runs at PR heads | CI outcome, slop signals | `GET …/commits/{ref}/check-runs` | Real pytest results converted by code |
| D11 | The git repository (full history, all PR heads) | Fixes, tests, blame for outcomes, code index | `git clone` | A real git repository built by code, exported as a bundle |
| D12 | Repository policy files: CODEOWNERS, MAINTAINERS, CONTRIBUTING, SECURITY, pyproject | Roles, hand-offs, build paths, repository notes | Files in the repository | Generated by AI as file content, committed in the real git history |
| D13 | Users (login, ID, type) | People, roles | Embedded `user` objects | Code (logins and display names by AI) |
| D14 | Consent records | Governance | Keeper's own UI | Code (synthetic consent rows) |
| D15 | Ground truth: planted slots per finding, per PR lane, per outcome | Evaluation only | — | Code, from the plan |
| D16 | Demo learner practice notes (before, learn, after) | Practice demo | Keeper's own UI | AI values for planned skill levels |
| D17 | Vulnerability data for dependencies | Hand-offs | OSV API | Live at runtime (not generated); the demo's new dependencies are real PyPI packages with known OSV entries, or none |
| D18 | Web context for unfamiliar packages | Hand-offs (optional) | Tavily API | Live at runtime when a key is configured |
| D19 | A second evaluation set | Optional robustness | CodeReviewer dataset (CC BY 4.0) | Not committed; download script |

## 3. Splits

| Split | Definition | Used for |
|---|---|---|
| `train_v1` | PRs created before `demo_now − holdout_months` (6) | Lens v1 |
| `holdout` | Reviewed PRs created in the last 6 months, closed before `demo_now` | Proof (v1), the growth residual, Practice items |
| `train_v2` | `train_v1` ∪ `holdout` | Lens v2 (with drift captured) |
| `live_queue` | Open PRs at `demo_now` | Queue (never trained on). Their ground truth (expected lanes and findings) is used only by `--eval`. |

## 4. Licensing of data

- **Demo data:** generated for this project and released under the repository's licence (Apache-2.0). It contains no real people.
- **Imported data:** review comments remain their authors' copyright. Keeper stores them locally for evaluation and lens building, attributes every quotation, and does not commit imported data to git. `.runtime/` is git-ignored, and only aggregate metrics go into the README.
- **CodeReviewer:** CC BY 4.0. Download it on demand, attribute it, and do not commit it.
