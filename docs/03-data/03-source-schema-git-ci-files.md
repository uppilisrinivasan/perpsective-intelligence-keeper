# Source schema: git, CI and repository files

## 1. The git repository

| Aspect | Real source | Demo |
|---|---|---|
| Transport | `git clone --mirror <url>` into `.runtime/repos/<project>.git`, then a worktree per job | `data/sources/git/<repo>.bundle`, created with `git bundle create <repo>.bundle --all`, and unbundled with `git clone <bundle>` into `.runtime/repos/<project>` |
| Refs needed | The default branch, and `refs/pull/<n>/head` for every PR (fetched with `git fetch origin '+refs/pull/*/head:refs/pull/*/head'`) | The bundle contains `refs/heads/main` and `refs/pull/<n>/head` for every PR, plus `refs/pull/<n>/merge`-free history (GitHub's synthetic merge refs are not needed) |
| Commit metadata | Real | `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_*` set by the generator from the plan |
| Merge style | As the project uses | Configurable per scenario: `merge` (merge commit, default), `squash`, or `rebase`. The PR JSON's `merge_commit_sha` is the resulting commit. |
| Reverts | `git revert -m 1 <merge_sha>` (message `Revert "<title>"\n\nThis reverts commit <sha>.`) | The same command, run by the generator |

Keeper uses git for: checking out PR heads (fixes and tests), `git blame` (outcome linking), building the code index (symbols per file at a commit), and computing diffs when the API's `patch` is absent.

## 2. Repository policy files (in the repository tree)

| File | Format | Keeper reads | Demo content (AI values, structure by template) |
|---|---|---|---|
| `CODEOWNERS` (root, `.github/` or `docs/`) | GitHub CODEOWNERS syntax: `<pattern> @owner …` | Path → owners, for hand-offs | `* @mira-k`; `/scripts/ @mira-k @theo-s`; `/strata/include*.py @mira-k @theo-s` |
| `MAINTAINERS.md` | Markdown list of `@login` with roles | Maintainer role | Mira (lead), Theo (security) |
| `CONTRIBUTING.md` | Markdown | The "Review" section becomes repository notes in the context block | Written by AI, including a few of the maintainer's rules explicitly. Most edge concerns stay **unwritten**, which is the point. |
| `SECURITY.md` | Markdown | A risk signal when changed | A short policy |
| `pyproject.toml` | PEP 621 | Dependencies (the `new_dependency` signal), the build system, Python versions, ruff configuration, test extras | `dependencies = []` (the "no runtime deps" invariant), `requires-python = ">=3.9"`, `[project.optional-dependencies] test = ["pytest==8.*"]` |
| `.github/workflows/ci.yml` | GitHub Actions YAML | A risk signal when changed | A matrix over Python 3.9–3.13 |
| `scripts/release.py`, `scripts/build_fixtures.py` | Python | Risk-signal paths | Small, real scripts |
| `tests/data/*` | Mixed, including binary samples | `test_fixture_binary` | A few small binary fixtures (generated by code, for example gzip-compressed sample configs) |

## 3. CI results

### 3.1 JUnit XML (pytest)

Produced by `pytest --junitxml=report.xml`. Shape (pytest's `xunit2` family):

```xml
<?xml version="1.0" encoding="utf-8"?>
<testsuites name="pytest tests">
  <testsuite name="pytest" errors="0" failures="1" skipped="0" tests="148" time="6.214"
             timestamp="2026-10-19T09:12:03.411208+00:00" hostname="ci-runner-3">
    <testcase classname="tests.test_include" name="test_escape_rejected" time="0.004">
      <failure message="AssertionError: …">…traceback…</failure>
    </testcase>
    …
  </testsuite>
</testsuites>
```

Keeper parses it with `xml.etree.ElementTree` (via `defusedxml`) in the fix loop. For the demo, the generator **really runs** pytest at every PR head and rewrites only `timestamp` and `hostname` to fit the timeline. The XML files are stored in `data/sources/ci/junit/<sha>.xml` (used by datagen to produce check runs, and kept for audit).

### 3.2 Check runs (GitHub API)

Each PR head has one check run per CI job: `name: "tests (3.12)"`, `status: "completed"`, `conclusion: "success" | "failure"`, `output.summary: "148 passed, 1 failed in 6.21s"`, `started_at` and `completed_at` from the plan (duration = the JUnit time plus setup overhead). Stored as `commits/<sha>/check-runs.json` in the GitHub mirror.

## 4. The code index (derived; not a source)

`keeper.analysis.codeindex.build(repo_path, sha)` produces `{path: {symbols: [{name, kind, line, end_line, public}], imports: [...]}}` using Python's `ast` module, cached per SHA in `.runtime/cache/codeindex/`. It is used for: the repository map in `fix_plan`, slop detection (nonexistent symbols), `touches_public_api` (changes to symbols exported in `__all__` or without a leading underscore in the public modules from `config/routing.yaml` `public_api_paths`), and mapping tests to areas.
